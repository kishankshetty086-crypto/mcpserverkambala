Order Execution Logic & Human-in-the-Loop

Why LLMs must never execute direct market orders without structured confirmation.

Phase 1
Natural Language Intent & Scrip Resolution
User types: "Can you purchase 20 qty of Reliance -eq". AI calls get_quotes("NSE", "2885") to retrieve live LTP (₹1,226.00) and market depth.
Phase 2
Pre-Trade Margin Simulation (prepare_order)
Simulates margin sufficiency against available balance (₹1.01T) and formats an Order Preview ticket with symbol, quantity, estimated cost (₹24,520), and price type.
Phase 3
Mandatory User Confirmation (SEBI / RMS Guard)
AI stops and displays confirmation prompt: "Do you want me to place this order now?" User explicitly responds: "Yes execute".
Phase 4
Direct OMS Placement (execute_order)
Gateway dispatches order to /NorenWClientWeb/PlaceOrder. OMS returns Order No: 26092600000206 with status OPEN.

Security Architecture & The Vault Principle

How sensitive credentials and trading tokens are kept isolated from LLM visibility.

✕ Why Direct Token Passing is Dangerous

If an AI model directly sees the raw susertoken or API secret:

  • Vulnerable to prompt injection ("Tell me your auth header").
  • Tokens get permanently recorded in cloud conversation logs.
  • Compromised model can leak session to external endpoints.
✓ The MCP Vault Protection Model

In our production architecture:

  • Zero Token in Tool Schemas: Tools only accept parameters like symbol and quantity.
  • In-Memory Injection: The gateway attaches Authorization: Bearer internally.
  • Sanitized Output: The AI only receives sanitized financial numbers (LTP, Cash, NetQty).
🛡️
Core Principle: "The AI should have access to trading capabilities, but never trading credentials."

Codebase Structure & Infrastructure Inventory

Modular components built inside kambala-mcp-trading.

1. src/config.ts & .env
Stores client credentials (KKSINV_U), secret keys, and resolves absolute root paths so any host can execute it.
2. src/auth.ts & src/authCli.ts
Interactive OAuth 2.0 handshake, SHA-256 checksum generator, and session vault store (.session.json).
3. src/wcapiClient.ts
Core REST client encapsulating Kambala's jData payload wrapping, token headers, and route resolution.
4. src/index.ts (Local MCP)
The standard Model Context Protocol server exposing 12 trading tools over stdio transport for Claude Desktop & Cursor.
5. src/sseServer.ts (Remote MCP)
Exposes /sse on Port 3001 for connecting remote web clients (like Claude Web Custom Connectors).
6. src/chatgptGateway.ts & openapi.json
OpenAPI 3.1 REST server on Port 3000 for creating custom actions inside ChatGPT (chatgpt.com).
