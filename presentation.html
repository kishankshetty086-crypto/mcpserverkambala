The Business Challenge

Why Traditional Bots Fail in Regulated Trading

SEBI / Compliance Mandate
The Unacceptable Risks of Naive AI Integration
  • ✕ Credential Leakage: Pasting API keys or user passwords directly into AI prompts exposes them to third-party model providers.
  • ✕ Unchecked Hallucinations: An LLM might hallucinate a ticker, reverse BUY/SELL, or invent trade quantities without strict pre-trade checks.
  • ✕ Regulatory Violations: Automatic trading without explicit human confirmation breaches exchange & broker mandate guidelines.
  • ✕ Zombie Sessions: When an admin terminates a trader session at 3:30 PM, bots remain stuck in loops without live invalidation.
The Kambala Model Context Protocol Solution
  • ✓ The Credential Vault: Session tokens stay isolated inside the private MCP gateway. AI assistants receive strictly typed JSON payloads.
  • ✓ Two-Phase Commit (Prepare $\rightarrow$ Execute): Pre-trade margin simulation is mandatory before the execution tool can be called.
  • ✓ Mandatory Human Confirmation: The AI presents an interactive order card and requires trader approval before sending packets to the exchange.
  • ✓ Live Broker Health Checks: Proactively queries Kambala WCAPI on connection to purge stale sessions immediately.

Engineering Deep Dive

4 Real-World Cloud & MCP Roadblocks Solved

Render.com + Claude Web
1. Render Module Not Found Build Phase

Render ran npm install but had no compiled dist/index.js.

Fix: Added "postinstall": "npm run build" and set Start Command to npm start.
2. Claude Connector 404 Probing Routing

Claude tested /mcp and / while server only listened on /sse.

Fix: Created universal route matching: app.get(['/', '/sse', '/mcp']) with SSE detection.
3. The Stream 400 Bug in SDK Critical Bug

express.json() drained the socket stream. When SDK called getRawBody(req), it threw HTTP 400 Bad Request.

Fix: Passed req.body as 3rd param: handlePostMessage(req, res, req.body).
4. DCR / Dynamic Client Registration Trap Auth Protocol

Claude expected Anthropic RFC 7591 OAuth metadata, conflicting with Kambala trader auth.

Fix: Configured Claude Connector as "No sign-in" with credentials securely vaulted in Render gateway.
AI Safety & Prompt Injection

Claude's Anti-Phishing Guardrail Uncovered

Anthropic Filter
What Triggered the Alarm

When the session expired, our tool error output contained:

"Please provide this login link to the user... Once the user logs in with their User ID, Password, and TOTP..."
Claude's security model flagged this as an indirect prompt injection / credential phishing attack, stating:
"That tool response is trying to get me to hand you a login link asking for your User ID, password, and TOTP... I won't relay it."
The Architectural Solution

We re-architected how authentication requirements are transmitted between tools and the AI:

  • 1. Zero URLs in Error Exceptions: Tool errors return clean, objective status codes (HTTP 401 Unauthorized) with no imperative commands.
  • 2. Structured JSON Data: The official login URL is returned inside regular JSON objects (loginUrl: "https://rama.kambala.co.in/..."), which Claude parses and renders safely.
  • 3. Out-of-Band Auth: Reconnection happens through the verified web portal or native connector interface, completely protecting the user.
Result: 100% compliance with Anthropic safety policies.
Authentication Protocol

Full 3-Legged OAuth & Live Lifecycle

Zero Zombie Tokens
STEP 1: INITIATE
Trader Opens Auth

Clicks 1-Click Login or opens /oauth/kambala. Redirects to official broker login page with client_id=KKSINV_U.

STEP 2: 2FA LOGIN
Kambala Portal

User authenticates on Kambala domain with User ID + Password + TOTP. Kambala issues one-time authorization code.

STEP 3: TOKEN EXCHANGE
GenAcsTok API

Server intercepts ?code=..., computes SHA256 checksum, calls /GenAcsTok, and vaults the 64-char susertoken.

STEP 4: LIVE MONITORING
Active Validation

When Claude connects, server queries /UserDetails. If admin logged out trader, dead token is wiped instantly.

Automatic Session Purge on Admin Logout: If admin terminates session at OMS, WCAPI returns 401 $\rightarrow$ Server executes clearSession() $\rightarrow$ Eliminates stale state.
