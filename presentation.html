How the MCP Server is Built & Handled in Domain

TypeScript / ESM

The gateway acts as a protocol bridge: on one side it implements the Model Context Protocol (MCP) specification using @modelcontextprotocol/sdk, and on the other side it implements the proprietary Kambala WCAPI REST specification.

1. Client Layer (wcapiClient.ts)

Encapsulates all communication with Kambala's /NorenWClientWeb/ endpoints. Formats outbound HTTP calls:

• Header: Authorization: Bearer <susertoken>
• Content-Type: text/plain
• Body: jData={"uid":"KKSINV","actid":"KKSINV",...}
• Auto-Purge: Wipes session on 401 Unauthorized
2. Dual Server Transports

The gateway supports two completely separate transport mechanisms depending on the environment:

• Local stdio (index.ts): Reads JSON-RPC from standard input and writes to output. Zero network latency.
• Remote SSE (sseServer.ts): Runs an Express server exposing /sse and /mcp for web AI clients.

Core Code Logic Snippet (sseServer.ts - Tool Declaration)

server.tool(
  'get_holdings',
  'Retrieve long-term Demat portfolio holdings and stock quantities.',
  {},
  async () => {
    try {
      const data = await client.getHoldings(); // Calls /NorenWClientWeb/Holdings (prd: "C")
      return jsonResponse(data);
    } catch (err) {
      return errorResponse(err); // If 401, returns structured loginUrl
    }
  }
);
Communication Pipeline

Start-to-End: How AI Reaches OMS / RMS

Detailed Data Path

Here is the step-by-step trace of what happens when a user types: "Show my Demat portfolio holdings".

01
User Prompt $\rightarrow$ Claude Tool Selection

Claude analyzes user intent against its active MCP tool definitions. It matches the prompt to tool get_holdings.

Claude generates: {"jsonrpc": "2.0", "method": "tools/call", "params": {"name": "get_holdings", "arguments": {}}}
02
Transmission over Transport Layer

If using Claude Web, Claude sends an HTTP POST with the JSON-RPC to /messages?sessionId=... on Render. If using Claude Desktop, it writes to standard input.

Server receives packet $\rightarrow$ routes to transport.handlePostMessage(req, res, req.body)
03
Session Vault Injection & Protocol Wrapping

The MCP server loads the vaulted susertoken (never exposing it to Claude) and wraps the request in Kambala's jData format.

POST to https://rama.kambala.co.in/NorenWClientWeb/Holdings
Body: jData={"uid":"KKSINV","actid":"KKSINV","prd":"C"}
04
OMS / RMS Database Lookup & Reply

Kambala OMS verifies trader session token, retrieves DP holdings from the back-office ledger, and returns JSON.

Response: [{"stat":"Ok","exch_tsym":[{"exch":"NSE","tsym":"RELIANCE-EQ"}],"holdqty":"100","upldprc":"1226.00"}]
05
Claude Synthesizes & Renders to User

Claude takes the raw JSON data and formats it into a clean, human-readable portfolio table showing symbol, quantity, and valuation.

Security Architecture

How Auth & Security is Handled (In Simple Terms)

Zero-Trust Isolation

1. The Token Vault (Zero Credential Leakage)

The most dangerous security flaw in AI bots is letting the LLM handle API keys or user passwords directly. In our architecture, the AI model has zero access to credentials:

  • Claude never sees your password, secret key, or session token.
  • The 64-character token (susertoken) lives strictly inside the private memory of the Node.js server.
  • The server automatically injects the token into outbound request headers to Kambala OMS.

2. The 3-Legged OAuth Handshake

Traders authenticate directly on Kambala's official domain:

1. Trader visits: https://rama.kambala.co.in/NorenWeb2.0/authorize/oauth?client_id=KKSINV_U&redirect_uri=...
2. Trader enters: User ID + Password + TOTP
3. Kambala redirects back to our server with: ?code=XYZ123
4. Server computes: SHA256(CLIENT_ID + SECRET_KEY + CODE)
5. Server calls /GenAcsTok and securely vaults the generated susertoken.

3. Live Connection Health Check & Auto-Purge

When Claude establishes an SSE connection, the gateway immediately pings Kambala's /UserDetails in the background. If an admin logged out the trader or market hours ended (HTTP 401), the server automatically calls clearSession(), purging the dead token from memory and disk so the server never operates in a zombie state.

OpenAI Integration

How to Setup in ChatGPT (Custom GPT)

OpenAPI 3.1 REST

ChatGPT uses **Custom Actions** with standard OpenAPI REST specifications rather than MCP. We have generated an OpenAPI schema at src/openapi.json.

Setup Steps in ChatGPT:
  1. Go to ChatGPT $\rightarrow$ Explore GPTs $\rightarrow$ Create.
  2. In the Configure tab, scroll down and click Create new action.
  3. In the Schema box, paste the contents of your src/openapi.json.
  4. Set Authentication to None (the gateway handles the broker token).
  5. Click Save. You now have an AI Trading assistant inside ChatGPT!
